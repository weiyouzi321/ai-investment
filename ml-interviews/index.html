机器学习岗位面试：终极指南

How I found a Research Scientist role after a PhD in Machine Learning

我觉得记录一下自己在 Machine Learning 博士毕业后找 Research Scientist 工作的经历可能会有帮助。网上关于这部分的资料几乎为零，我刚开始时也希望有人写过类似内容。如果你正在准备，或者只是好奇整个过程，希望这篇能帮到你。

总体而言，我的求职过程是成功的：凡是我完成全部面试的公司，都发了 offer，包括 DeepMind（已接受）、Isomorphic Labs、Cohere、Meta 以及一家 stealth 模式初创。需要补充一点的例外是：Anthropic、Mistral 和 TeslaAI 回复太晚，我没有完成流程；ReflectionAI 则是我唯一的真正拒信——他们不认可我的 RS 岗位，但把我转到了 Engineering 通道。

我大多数申请都拿到了面试邀请，除了 SpaceXAI、Waymo 和 Wayve。至于 SpaceXAI，我当时确实让一位朋友帮我写了申请材料……

如何拿到面试

拿到面试的核心线索是：内推和主动联系（cold email）比海投有效得多。尽可能找你认识的同事或校友内部推荐，降低筛选门槛。

另一方面，如果是冷启动，一封包含 2-3 个工作相关洞见、且简短到可以快速读完的邮件，更容易获得回复。常见误区是写得像求职信一样冗长。

初创 vs 大厂

如果你在意长期成长空间和系统性基础设施，大厂通常提供更深的领域积累和资源；但初创能让你更早接触完整产品和业务链路。

不要只盯着品牌。建议从“做的事情 + 团队 + 你的直属领导”三个维度评估，而不是只看公司名字。

关于薪酬：RSU vs 期权

RSU 更常见于上市前后阶段公司，发放时期权结构简单；期权（Options） 通常增值空间更大但伴随不确定性，需评估行权成本和税务影响。

许多候选人会直接用“总薪酬（TC）”来比较，但要注意 sign-on、 relocation、refresh 频率等因素。

面试结构

典型的 Research Scientist 面试流程常包括：

  1. Hiring manager / 团队聊天
  2. 论文深挖（paper presentation + Q&A）
  3. 算法 / LeetCode 题目
  4. 机器学习系统或实现题（coding + ML reasoning）
  5. 行为 / 情商类问题
  6. 全流程之后往往还有 negotiation 阶段

不同公司对结构会有增减。例如 DeepMind 更看重复现论文思路的清晰度；Meta 则加系统设计类题目。

技术准备

Flashcards

把常见概念、论文的核心图表、常见误区做成闪卡（anki 等），利用碎片时间反复记忆。

用 LLM 做模拟面试

让 Claude 或 Gemini 作为面试官来问问题，练习在大约 30 分钟内把逻辑说清楚。重点不是背诵，而是训练“一句话把问题讲明白”的节奏。

LeetCode / NeetCode

建议按公司标记高频题，并进行时间约束练习。许多工程师岗位考得更深，RS 一般只要求中等难度，但基础 MUST PASS。

书籍

  • Algorithm Design — Kleinberg & Tardos
  • Deep Learning — Goodfellow, Bengio, Courville
  • Designing Data-Intensive Applications — Martin Kleppmann

课程

需要的课程很多，真正受益的反而不是某一门，而是建立“从数学推导到工程实现”的桥接理解。

机器学习代码和调试

面试前确保 batchnorm 的 moving average、随机种子、分布式数据并行这些细节能讲清楚。能被问到的机会比预期高。

心理准备

先处理现实问题

不要等状态完美再投。焦虑本身会形成“等状态好一点再开始”的死循环。建议设置固定申请量（例如每天 2–3 家），保持节奏。

面试前的仪式

建立一个稳定流程：环境、白噪音、桌面状态、摆放水杯；在正式开始前做 2 分钟呼吸。这些细节对压力下的表达稳定性有帮助。

更难的部分

被拒是常见体验。把每次面试当成一次信息收集，而非考试；收集“我对这个领域理解不足”的精确问题，然后集中补。

有帮助的书籍

  • Thinking, Fast and Slow — Daniel Kahneman
  • Atomic Habits — James Clear
  • The Charisma Myth — Olivia Fox Cabane

流程准备

面试前确认时区、平台、网络、备用设备。把面试链接和公司联系人信息放在同一个文件夹里，减少临场搜索。

行为问题的准备建议写成 8-10 条故事模板，每条覆盖：

  • 情境 / 任务 / 行动 / 结果
  • 你在决策中的个人具体贡献
  • 量化指标（即使只是近似）

谈判

拿到第一个 offer 后应积极同步其他流程，创造竞争性压力。

谈判不仅是数字游戏，还涉及 you-know-what 的其他条件：签字费（sign-on）、股票 refresh、搬家支持、试用期条款等。如果公司诚意足够，relocation 和 sign-on 最容易成谈判杠杆。

决策过程

我按以下权重维度做排序：

  • 研究自由度 + 资源充足度
  • 团队能力与导师质量
  • 长期影响（是否让你变得更值钱）
  • 地理位置 / 生活成本 / 税率

只有在两个选项都能改善你未来形态时，这才是一个好决策问题。如果只能“赌大公司光环”，那决策其实是被动接受。

如果要重来

  • 更早开始系统投；不要等论文投出去再做求职。
  • 与面试官建立连接，而不只是展示能力。
  • greedy 地主动提出想做的方向，而不是等分配。
  • 更重视获客渠道：内推和作者身份（blog / GitHub）带来高质量信号。

技术主题

以下是我在面试中被问到的高频主题集群：

  • 统计学基础：概率、假设检验、贝叶斯思维、分布直觉
  • 优化：凸优化、随机优化、梯度下降变体、正则化
  • 深度学习：反向传播、初始化、归一化、正则化、注意力机制
  • ML 系统：数据 pipeline、特征存储、离线/在线评估、延迟与吞吐权衡
  • 论文阅读：能复述关键实验、对照基线、局限性和改进方向
